# 複数動画の継続解析

2026-10-26 JSTのユーザー依頼で、同じ許諾済み投稿者の複数公開動画の並行解析を承認。
対象はステバイ @steby0419 の「みんなでダービー2」。各動画の投稿者・シリーズをブラウザで確認する。
原要件の当該投稿者の分析・フレーム抽出許諾申告を根拠とし、他投稿者・別シリーズへ拡大しない。

## 継続実行
このチャットの時間ごとのheartbeatで、小さな区間単位の収集を再開する。
最大2動画の解析を並行実施。各担当は動画別ディレクトリへpacketを保存し、DBは親が直列に登録する。
共有ブラウザUIが干渉する場合は取得だけ直列化し、画像解析は並行化する。
実行環境はローカルPC。PCとアプリが実行可能で、Chrome接続が使えることが前提。
常時稼働のcloud workerやYouTube Data API discoveryは未実装であり、無停止の常駐処理は保証しない。

## 保存と再開
状態は sibling outputs/observation-ledger/processing-queue.json、DBはobservations.sqlite3。
証跡はevidence/{video_id}-{batch_id}/へ追記。画像hash・時刻・confidence・NULL理由を必須とする。
指定時刻と実停止時刻を区別し、広告・buffer・画角欠損を検出/記録する。
captureの前後で実watch URLのvideo IDと対象を照合する。別動画へ変わっていれば保存を中止し、専用タブで再確認する。
実取得した区間、再開位置、限定retry、失敗/ブロッカー理由を毎回キューへ保存する。
未処理動画が不足したら同投稿者の動画一覧からタイトル/画面で本シリーズと確認できる公開動画を候補追加する。
各候補のURL・表示投稿者・シリーズ確認根拠を残し、確認前はpermission pendingで解析しない。
未取得区間を完了と記録しない。画面にない値や馬名を補完しない。
品質除外でも部分観測を先に蓄積し、元データ・画像は更新/削除しない。
既存画像の再読取は元candidate_race_idを維持して独立出現数を増やさない。
新動画のrace identityが未確定なら候補のまま保存し、既存レースへ推測結合しない。

## 報告
通常の作業進捗は運用ログへ保存し、ユーザーへの保存状況報告は日本時間毎朝9時に1回。
日次は動画数、新規/累計項目数、馬名候補数、検証状況、画像数、待機/失敗状態を簡潔に示す。
daily-report-state.jsonで報告済み日付と前回件数を管理し、同日重複報告を防ぐ。
項目数にはNULL/再読取を含むことを明記し、独立出現数と混同しない。
同じ画像の複製はSHA256で重複排除して画像数を数える。
閲覧用CSV/summary/statusは `python scripts/export_observation_ledger.py --directory ../observation-ledger` で更新する。
GCP課金設定・有料API・ストリーム直接取得は行わない。
